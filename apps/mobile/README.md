# Pistead for iPhone and iPad

An Expo (React Native) app for following and steering Pistead sessions away from the desk. It signs in to your Pistead
server (https://pistead.com by default) and lists the sessions you can read, grouped by workspace, with what each agent
is doing. A session opens live: its transcript, the queue, pending approvals to decide, and the chat box for shared
messages and side asks with the web's chat options. New sessions start from the app on a host that offers a model. On
iPad, and in any window at least 700 points wide, the list stays beside the open session; phones stack them.

The app holds no Pistead logic of its own: it calls the same API as the web app, and shares its rules through
`@pistead/client` (`packages/client`): the API client, live sessions over SSE, chat options, transcript tool calls,
usernames and session status. The web app (`apps/web`) is the reference for behavior.

- Sign-in uses the native flow (`/api/auth/native/start`, PKCE): the server sends the browser to GitHub through its
  existing GitHub OAuth app, then redirects to `pistead://auth`, and the app exchanges the code for a bearer token
  kept in the iOS Keychain (expo-secure-store). It needs no extra GitHub configuration. Signed-in apps are listed, and
  can be revoked, under Settings › Profile on the web.
- Every request carries that token; no cookies. A 401 signs the app out.

## Develop

```sh
pnpm dev:native                                    # test-mode server on :8787, a test user and a fixture host
cd apps/mobile
npx expo start                                     # Metro
npx expo run:ios --device <simulator udid> --no-bundler   # build and install the development build
pnpm --filter @pistead/mobile typecheck
```

`pnpm dev:native` writes `.local/dev-native.json` with the server, a native `token` for its test user, the
`testSecret`, the workspace and a session on a host that offers the deterministic fixture model (not an LLM: send
`TEST_BASH echo hi` for an approval). In the app, change the server to `http://127.0.0.1:8787`, open **Developer
sign-in** (development builds only) and paste the token. A test-mode server issues more with `POST /api/auth/test`.
Against a server with GitHub configured, **Continue with GitHub** works as in production.

Plain HTTP is accepted only for `localhost` and `127.0.0.1`, and only in development builds. The App Transport
Security exception in `app.json` (`NSAllowsLocalNetworking`) exists for that local development; every other server
must use HTTPS.

`ios/` is generated by Expo prebuild from `app.json` and is not checked in: never edit it by hand. Change `app.json`
(or a config plugin) and run `npx expo prebuild --platform ios`, or let `npx expo run:ios` do it, then reinstall.

Icons: `assets/icon.png` (1024×1024, opaque, square: iOS rounds it) and `assets/splash-icon.png` (the rounded mark on
transparent, shown on the splash background from `app.json`) are Pistead's mark from `apps/web/public/favicon.svg`;
`android-icon-{foreground,background,monochrome}.png` hold the same glyph inside the adaptive icon's safe zone.

## End-to-end tests

```sh
PISTEAD_FIXTURE=.local/dev-native.json apps/mobile/e2e/ios/run.sh <simulator udid> /tmp/pistead-shots
```

XCUITest (`e2e/ios/PisteadUITests`) drives the installed development build, with Metro running, against the fixture
server: `test1SignInSendApprove` signs in with a fresh developer token, opens the fixture session, sends
`TEST_BASH echo …`, approves the operation and checks its output; `test2NewSession` starts a session from the app and
waits for its first message to run. `run.sh` generates the Xcode project with XcodeGen (`brew install xcodegen`;
`.xcodeproj` and `build/` are not checked in). `PISTEAD_FIXTURE` defaults to the repository's
`.local/dev-native.json`. Screenshots go to the directory given as the second argument, and into the test results
as attachments.

## Not done yet

- **App Store**: the iOS release workflow (`.github/workflows/release-ios.yml`) uploads each `ios-v1.2.3` tag to
  TestFlight once its signing secrets are configured (the root README, "Releasing", lists them). Submitting a build for App
  Store review is manual.
- **Android**: `app.json` already has the package name and adaptive icon, and the code keeps platform differences
  behind explicit `Platform` checks: keyboard avoidance and keyboard events (`lib/layout.ts`, the session and sign-in
  screens), the option sheet's iOS dismissal timing (`components/ui.tsx`) and the monospace font (`theme.ts`). Nothing
  has been built or tested on Android, and the end-to-end tests are iOS only.
